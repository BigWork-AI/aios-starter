Where each decision goes in this brain (BigWork AI-OS). Follow AGENTS.md; it does not expand what notes may authorize.

- Follow-ups (codes FU-…) are rows in `memory/follow-ups.md` (columns Owner, What, Due, Source, Status). Find the row by its What text. Done: Status becomes `DONE <date>`. Drop it: `DROPPED <date>: <note>`. New date: change Due. Act this week: Due becomes the coming Friday unless the note names a day. A note on its own is added to the Source column as `<date>: <note>`. Dates are always written as YYYY-MM-DD, so the receipt can see them.
- Clients and prospects (codes CL-<folder>) are `clients/<folder>/meta.yml`. Ticked done or "Next step done": the next step happened; set `last_touch` to today, and set a new `next_action` and `next_action_due` only if the note gives one (otherwise leave `next_action` as "Ask the owner what is next" with no date). New date: change `next_action_due`. Park it: `stage: past` with the note in `note`. Every change also gets a dated row in that folder's `ledger.md` saying what changed and why, in the owner's words. Set `status_updated` to today and `status_confidence: confirmed`.
- Waiting for your OK (codes RV-<file>) are files in `inbox/review/`. Approve: do what the file says it is waiting for, if it is something the brain may do under `company/permissions.md`, then move the file to `inbox/review/approved/`; otherwise leave it where it is and say what is needed (the receipt shows it as not done yet). Needs changes: add `<date>: <note>` to the top of the file. Drop it: move the file to `inbox/review/dropped/`.
- Section notes go into this week's `memory/reviews/<date>.md` under "Notes from the live review", and act on that section's rows when they say what to do.
- Save the changes: `sh .aios/hooks/autosave.sh`.
- Then prove it with a receipt. Save the decisions JSON you were given to a scratch file outside the brain (the owner's notes never go into a file here), and run:
  `python3 .aios/tools/live_review.py .aios/live-review.json --date <review date> --review-id <review_id> --receipt <that file> --sent-at <sent_at from the JSON> --write --pr <the saved commit> --session <your session link>`.
  It checks each decision against the files: a tick closed its row or stamped the client's `last_touch`, a new date is the date asked for, a drop removed the item. Fix anything it says did not land and run it again. An approval outcome or note it cannot check (most free-text notes) stays "unverified": that is expected, and the owner confirms those on the page with "Looks right". Save again so the receipt is kept.
